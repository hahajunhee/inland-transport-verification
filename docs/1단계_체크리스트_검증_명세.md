# 1단계 체크리스트 검증 — 개발자 명세서

> 정산 엑셀 업로드 시 **데이터 정합성**을 8개 Stage로 사전 점검하는 기능.
> 요율 비교(2·3·4단계)와 무관하게, "이 엑셀이 검증에 적합한 형태인가"를 먼저 확인한다.
> 작성 기준 버전: `app/__init__.py` 기준 최신 (문서 작성 시점 v1.7+)

---

## 1. 파일 위치 (어디를 보면 되나)

| 역할 | 경로 | 설명 |
|------|------|------|
| **비즈니스 로직** | `app/services/checklist_service.py` | 파싱 + Stage 1~8 검증 + 세션 저장 + 리포트 생성. **핵심 파일.** |
| **API 라우터** | `app/routers/checklist.py` | 업로드/Stage7/세션목록/휴일/다운로드 엔드포인트. prefix `/api/checklist` |
| **페이지 라우트** | `app/routers/pages.py` 의 `/checklist` | `templates/checklist.html` 렌더 |
| **화면(UI+JS)** | `templates/checklist.html` | 업로드 폼, Stage별 결과 카드, Stage7 입력창. **JS는 이 파일 내 인라인 `<script>`** (별도 .js 없음) |
| **세션 저장소** | `data/checklist/session_{id}.json` | 업로드 1건 = 세션 1개. 검증결과+원본행 통째 저장 (git 제외) |
| **사용자 휴일** | `data/user_holidays.json` | Stage 3에서 사용하는 사용자 지정 공휴일 목록 (`["2026-01-01", ...]`) |

> ⚠️ 다른 단계와 달리 체크리스트 세션은 **SQLite DB가 아니라 `data/checklist/` 의 JSON 파일**로 저장된다. (`data_store` 미사용. 단, Stage 5의 매핑 조회는 `data_store.load("port_mappings.json"/"odcy_mappings.json")` 사용)

## 2. 전체 데이터 흐름

```
[엑셀 업로드]  POST /api/checklist/upload
      │
      ▼
parse_checklist_excel(bytes)          # 헤더행 자동탐지 → 행 dict 리스트
      │
      ▼
run_checklist(filename, rows)         # Stage 1,2,3,4,5,6,8 일괄 실행 (★ 7번 제외)
      │   └─ _refresh_holiday_set()   # 사용자 휴일 로드
      │   └─ 세션 JSON 저장 (errors 포함)
      ▼
[결과 반환]  error_counts + errors + stage_names

[Stage 7 직상차]  POST /api/checklist/stage7/{session_id}   ← 사용자가 컨테이너번호 입력 후 별도 호출
      │
      ▼
run_stage7(session_id, container_numbers)  # 세션 로드 → check_stage7 → errors["7"] 갱신·재저장

[리포트]  GET /api/checklist/download/{session_id}  → generate_checklist_report() → .xlsx
```

**중요 포인트**
- Stage 1~6, 8은 업로드 즉시 자동 실행된다.
- **Stage 7(직상차)만 인터랙티브**: 사용자가 직상차 대상 컨테이너 번호 목록을 textarea에 입력 → 별도 API 호출로 검증. 건너뛸 수 있음(선택).
- 업로드 응답의 `error_counts`에는 Stage 7이 빠져 있다(`("1","2","3","4","5","6","8")`만 집계). 7은 나중에 채워짐.

## 3. 엑셀 파싱 규칙 (`parse_checklist_excel`)

- `pd.read_excel(BytesIO, header=None, dtype=str)` 로 전체를 문자열로 읽음.
- **헤더행 자동 탐지**: 각 행에 `"Cont.Category"`, `"픽업지"`, `"D/G여부"` 중 하나라도 있으면 그 행을 헤더로 간주. 못 찾으면 `ValueError`.
- 헤더행 다음부터 데이터. `CHECKLIST_COLUMN_MAP` 으로 엑셀 열제목 → 내부 키 매핑.
- **빈 행 스킵**: `pickup_code`(픽업지)가 비어 있으면 그 행은 건너뜀.
- `row_number` = 엑셀 실제 행번호 (1-based, 오류 표시용).

### 컬럼 매핑 (`CHECKLIST_COLUMN_MAP`)
오타·표기 변형을 흡수하기 위해 여러 엑셀 열제목이 같은 내부 키로 매핑된다.

| 엑셀 열제목 | 내부 키 | 비고 |
|---|---|---|
| `Contrainer No.` / `Container No.` | `container_no` | 원본 오타(Contrainer)와 정타 둘 다 허용 |
| `C/Invoice No.` | `c_invoice_no` | |
| `픽업지` / `픽업지명` | `pickup_code` / `pickup_name` | |
| `출하지명` | `departure_name` | |
| `도착지` / `도착지명` | `dest_code` / `dest_name` | |
| `상세 ODCY` / `상세 ODCY명` | `odcy_code` / `odcy_name` | |
| `ODCY도착지명` / `ODCY 도착지명` | `odcy_destination_name` | 공백 유무 둘 다 |
| `출하일` | `transport_date` | |
| `ODCY 반입일` / `ODCY 반출일` | `odcy_in_date` / `odcy_out_date` | |
| `터미널 반입일` | `terminal_in_date` | |
| `선적일` | `shipping_date` | |
| `D/G여부` | `dg_flag` | |
| `Cont.Category` | `cont_category` | RE=리퍼 |
| `Frozen Container` | `frozen_container` | "X" 체크 여부 |
| `Weekend / Holiday` | `weekend_holiday` | "X" 체크 여부 |
| `ODCY` | `odcy_col` | 값이 `PORT_DRT`면 직반입 |
| `Waiting (ODCY)` | `waiting_odcy` | 직상차 표시 "X" |
| `운송유형` / `운송모드` | `transport_type` / `transport_mode` | 운송유형=왕복/편도 |

## 4. Stage별 검증 로직 (상세)

> 모든 오류는 `{row_number, container_no, column, value, reason}` 형태의 dict로 누적된다.
> 함수: `check_stage1` ~ `check_stage8` (`checklist_service.py`).

### Stage 1 — 필수 항목 공란 체크 (`check_stage1`)
1. **항상 필수 (공란이면 오류)**: 픽업지명, 출하지명, 도착지명, 출하일, 터미널 반입일, 선적일
2. **ODCY 직반입 분기** — `ODCY` 열(`odcy_col`) 값이 `PORT_DRT`인지로 분기:
   - **PORT_DRT(직반입)인 경우**: 상세 ODCY / ODCY 반입일 / ODCY 반출일 / ODCY 도착지명에 **값이 있으면 오류** (직반입은 ODCY를 거치지 않으므로 비어 있어야 함).
   - **PORT_DRT가 아닌 경우**: 위 4개 ODCY 항목이 **공란이면 오류** (필수).

### Stage 2 — 리퍼 / DG 체크 (`check_stage2`)
- `Cont.Category == "RE"`(리퍼)인데 `Frozen Container != "X"` → 오류 (리퍼면 Frozen 체크 필요).
- `D/G여부` 열에 값이 있으면 → 오류 (**이 열은 공란이어야 함**).

### Stage 3 — 공휴일 / 주말 체크 (`check_stage3`)
- 기준일 = **출하일**(`transport_date`).
- "휴일" 판정(`_is_holiday_or_sunday`): **일요일(weekday==6)** 또는 **사용자 지정 공휴일**(`data/user_holidays.json`).
  - ⚠️ **토요일은 휴일로 보지 않는다.** 토요일을 휴일 처리하려면 사용자 휴일에 등록해야 함.
- 출하일이 휴일인데 `Weekend / Holiday`가 미체크 → 오류.
- 출하일이 평일인데 `Weekend / Holiday`가 "X" 체크됨 → 오류.
- 휴일 목록은 `POST /api/checklist/holidays` 로 등록/수정.

### Stage 4 — 운송유형 / 모드 누락 체크 (`check_stage4`)
- `운송유형`(transport_type), `운송모드`(transport_mode)가 공란이면 오류.

### Stage 5 — 왕복 / 편도 체크 (`check_stage5`)
픽업지와 도착지의 **포트구분(PM-B)** 이 같으면 `왕복`, 다르면 `편도` 여야 한다. 실제 `운송유형` 값과 비교.
- 픽업지명 → `port_mappings.json` 의 `excel_name(PM-A)` 매칭 → `port_type(PM-B)` 획득. (매핑에 없으면 스킵)
- 도착지 판정은 **ODCY도착지명 유무로 분기**:
  - **ODCY도착지명 있음**: `odcy_mappings.json`에서 `odcy_destination_name(OM-A)` → `odcy_location(OM-D)` 획득 → `_om_d_to_port()`로 포트 변환
    - OM-D ∈ {`KRPUSN`, `PUSN16`, `PUSN7`} → **부산신항**, 그 외 → **부산북항**.
  - **ODCY도착지명 공란**: 도착지명 → PM-B로 변환해 비교.
- 기대값(`왕복`/`편도`) ≠ 실제 `운송유형` → 오류 (reason에 변환 근거 detail 포함).

### Stage 6 — 일자 순서 체크 (`check_stage6`)
- 다음 순서로 날짜가 **단조 증가**해야 함:
  `출하일 → ODCY 반입일 → ODCY 반출일 → 터미널 반입일 → 선적일`
- 값이 있는 날짜들만 추려서 인접 비교, 뒤 날짜가 앞 날짜보다 **이전**이면 오류.
- (공란인 날짜는 비교에서 제외)

### Stage 7 — 직상차 체크 (`check_stage7`) ★ 인터랙티브
입력: 사용자가 직상차 대상 **컨테이너 번호 목록**(textarea, 줄/구분자 입력).
1. **입력한 컨테이너**: 검증파일 `Container No.`에서 검색
   - 파일에 없음 → 오류("존재하지 않습니다")
   - 있는데 `Waiting (ODCY) != "X"` → 오류 (직상차인데 Waiting 미체크).
2. **입력하지 않은 컨테이너**인데 `Waiting (ODCY) == "X"` → 오류 (직상차 목록에 없는데 체크됨).
- 결과는 세션의 `errors["7"]`에 저장(재호출 시 갱신).

### Stage 8 — C/Invoice No. 도착지명 정합성 (`check_stage8`)
- **같은 `C/Invoice No.`** 인데 **도착지명이 2종류 이상**이면, 그 인보이스의 **모든 행**을 오류로 표시.
- (한 인보이스는 도착지명이 하나여야 한다는 규칙)

## 5. API 엔드포인트 (`/api/checklist`)

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/upload` | 엑셀 업로드 → Stage 1~6,8 실행. 응답: `session_id, filename, total_rows, error_counts, errors, stage_names` |
| POST | `/stage7/{session_id}` | body `{container_numbers: [...]}` → Stage 7 실행. 응답: `errors, count, total_containers` |
| GET | `/sessions` | 최근 세션 목록(최대 20) |
| GET | `/holidays` | 사용자 휴일 목록 |
| POST | `/holidays` | body `{dates: ["YYYY-MM-DD", ...]}` → 휴일 저장(중복 제거·정렬) |
| GET | `/download/{session_id}` | 검증결과 엑셀(.xlsx) 다운로드 |

## 6. 리포트 엑셀 구조 (`generate_checklist_report`)

- **시트1 "요약"**: 파일명/업로드일시/총행수 + Stage별 오류 건수 + 총 오류 건수.
- **시트2 "전체 오류 목록"**: `Stage / 검증 항목 / 행번호 / 컨테이너번호 / 열 / 현재값 / 오류 사유` (Stage 1→8 순서, 오류행 연분홍 음영, 자동필터·틀고정).

## 7. 개발자 참고 / 주의사항

- **Stage 번호와 실행 순서**: UI·리포트는 1~8 순서지만, 코드상 `run_checklist`는 업로드 시 **1,2,3,4,5,6,8만** 실행하고 **7은 별도**다. `STAGE_NAMES`(`checklist_service.py`)에 8개 모두 정의.
- **세션 저장 위치**: `data/checklist/session_{id}.json`. ID는 기존 파일들의 `session_N` 중 최대값+1. (DB 아님)
- **휴일 정의**: 일요일 + 사용자 휴일만. **토요일 제외**.
- **Stage 5 의존성**: `port_mappings.json`(PM-A→PM-B), `odcy_mappings.json`(OM-A→OM-D)에 매핑이 없으면 해당 행은 **검증 스킵**(오류 아님). 요율등록 화면에서 매핑을 먼저 채워야 정확.
- **PORT_DRT(직반입)**: `ODCY` 열 값이 `PORT_DRT`이면 ODCY 관련 항목이 비어 있어야 정상(Stage 1).
- **빈 행 처리**: 픽업지 공란 행은 파싱 단계에서 제외되므로 검증 대상이 아님.
- **컬럼 오타 흡수**: `Contrainer No.`(원본 오타)와 `Container No.` 둘 다 인식. 추가 표기 변형이 생기면 `CHECKLIST_COLUMN_MAP`에 키만 추가하면 됨.
